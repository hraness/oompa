# Darwin personal daemon restart acceptance

Status: source implementation and independent review are complete; focused validation is pending. No native daemon, SQLite, provider, or authentication acceptance has run for this plan.

The existing personal Claude continuation path can run under a fresh live-acceptance installation while the managed Mac policy remains guarded. This plan proves a bounded authenticated continuation across joined daemon generations, then preserves one deliberately ambiguous local input without replay. It does not activate production or qualify managed Mac execution.

1. Reuse the existing owner-terminal authentication and seed-session implementations through an internal custody interface. Keep their public seventeen-operation session entry unchanged. A separate daemon seed factory owns nine fixed operations, a fresh short private root, a distinct owner namespace and the original durable process/frame tickets.
2. Start the ordinary daemon against fresh test state and the exact authenticated test profile. A guarded observational hook retains the product's actual runtime resolver and process factory. Production installations reject the hook before opening state. The hook cannot transform outbound bytes or replace process identity/output/exit.
3. Complete a normal nonce turn, stop and collect the first daemon and its provider root/streams. Restart the same state and provider thread, complete a second nonce turn, then withhold exactly one acknowledgment after the original local stdin write fulfills. Preserve the product's ambiguous mutation and independent process collection.
4. Restart once more, submit the exact same idempotency request and require the existing recovery response with no attempted user write and an unchanged retained intent. Stop and collect the third daemon. Retain all private roots and authentication for explicit later disposition.
5. Independently review source, run focused pure checks and repository-required integration checks. An admitted exact-source owner invocation, real authentication, joined child custody and live results are separate acceptance gates. Never substitute synthetic reducer success for those observations.

The private journal records the exact descriptor before each child starts, then six fixed command intents before adoption, import, normal sends, the deliberate ambiguous send and its same-key retry. Every command is copied before its first asynchronous persistence step and bound to the current daemon generation and nonce. Unknown receipt writes close admission permanently for that owner.

The parent retains each child stdin writer. EOF or extra descriptor input withdraws daemon lifetime. Parent withdrawal synchronously aborts every captured ordinary transport signal, including a request still awaiting capability or socket validation. The fixed Bun child disables automatic package installation. Unknown effects, missing joins and uncertain receipt writes retain the attempt; there is no retry, cleanup-by-PID, new provider writer or opportunistic logout.

Pure evidence so far: the observational adapter passed six fake-child cases with 34 assertions; the production-hook rejection passed one case with two assertions. These checks execute no provider or SQLite operation. The independently authored reducer passed ten cases with 429 assertions plus strict TypeScript and lint. Independent review covered the CLI hook, actual observer, no-replay counter, exact child lifecycle, descriptor and durable command journal. The native driver has source but remains unexecuted; final integration and owner acceptance remain pending.
