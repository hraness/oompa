# Model routing and bounded autonomy

Domain update, 2026-09-10: [the current domain plan](./oompa-app-domain.md) supersedes earlier host choices in this record. Current website and app destinations are `oompa.app` and `app.oompa.app`; prior hosts grant no current routing or authentication authority. Dated delivery evidence remains historical.

## Outcome

Make Sol Ultra the authoritative default for every implicit new Codex session, then add a conservative and explainable routing framework that can be evaluated without changing live sessions. Later phases may admit additional model profiles, exact Work provisioning, notification timing, and bounded supervision only after their capability, privacy, recovery, and holdout gates pass.

The public benchmark survey selects candidates for local evaluation. It does not license a live routing rule. Frozen 2026-09-05 capability evidence recorded Sol and Astra in the then-observed Codex 0.153.2 catalog, but that is historical contract evidence rather than proof that the current owner account can run Astra. The 2026-09-06 correction binds new and explicitly selected Codex `high` and `ultra` routes to Sol. Neither change licenses Terra, automatic Fast, or live shadow routing.

## Constraints

- Preserve the durable identities of `low`, `high`, `ultra`, and `fable-max`. Historical Devin `astra` rows remain exact contract 2 read-only evidence and never regain execution or selection authority. Existing supported sessions stay bound to their previously admitted exact model and effort; new or explicitly changed Codex `high` and `ultra` selections resolve to Sol.
- Routing is performance policy only. It never changes approval mode, sandboxing, permissions, account, project, execution device, or remote-action authority.
- Unknown, ambiguous, open-ended, safety-relevant, network, MCP, authentication, release, migration, and cryptographic work stay on the strong admitted profile unless an exact declared Work effect class proves otherwise.
- Never rotate accounts to evade limits, replay a failed turn on another model automatically, or automatically change model, effort, provider, or service tier after a conversation has begun. Explicit changes among supported presets and providers remain available through their existing fenced commands.
- Fable and any later Claude profile require explicit Claude selection. No automatic cross-provider data transfer is introduced.
- Private task text, transcripts, paths, account labels, provider credentials, and model output never enter committed fixtures or content-free receipts. Evaluation reads only an explicit owner-provided input path.
- Keep Work route matching exact. A relative rule such as "tier or above" has no stable meaning across provider families and would weaken an authority fence.
- Hosted storage remains unable to read encrypted projected conversation content. No plaintext ask, prompt, answer, transcript, or command enters Convex or email without a separately accepted privacy design.
- The released notification-hours record remains notification-only. A separate, default-off after-hours autorespond policy may later use the same immutable schedule snapshot to choose between approved budget tiers; hours never change approval categories or execution authority.
- Sanitised command classes and permission-category labels are presentation data, never authority. `auto:workspace` leaves every command and permission grant pending until a provider-specific adapter attests the complete private authority against the bound canonical project root. File-change acceptance remains pending while exact affected paths are unavailable.
- State changes use append-only, transactional, downgrade-tested migrations. Existing public beta state is treated as real.
- Follow [CONTRIBUTING.md](../../CONTRIBUTING.md#final-validation) for final source admission: independently reviewed, coverage-equivalent complete `Required` CI on the exact current-base integration tree, plus every explicit local, browser, native, installation and operational requirement. Use `bun run check` as the local aggregate where required or equivalence is uncertain. Broad local checks use the installed Oompa host scheduler without changing the child command.
- The integration owner owns convergence files: preset and runtime contracts, storage schemas, daemon service, CLI parser, cloud unions, Convex schema, app screens, package manifests, plan indexes, and release-facing documentation.
