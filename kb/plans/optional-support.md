# Optional product updates and development support

## Scope and decisions

Use the reviewed shared support foundation for explicit `oompa support` commands and brief agent discovery after typed useful standalone results. Keep task stdout unchanged, programmatic calls quiet by default, and provider payloads uninspected. Help, account/authentication, daemon controls, pending work and event polling do not qualify. Provider agent sessions are independent workflows; preserve explicit support disable preferences through their sanitized environments.

The human chooses free product updates or paid development support on Hraness Accounts. A local invitation is never a signup, payment, account-status check or proof that a person read it. The native menu uses explicit clicks and the website uses the shared footer. Existing capacity, daemon startup, hosted-writer and intended-target gates remain in force.
