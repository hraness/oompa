# Guidelines

- Keep this boundary outside production imports and package entrypoints. The native adapters require separate fresh launch authority; they do not enable a runnable live qualification command.
- Preserve the exact Claude pin and the managed-macOS production guards. A synthetic fixture result is never live qualification or activation authority.
- Metadata documents stay inside the protected account reader. Normalized identity tuples and status bytes belong only inside the private observer/projector. Receipts contain run-local keyed tags; public output contains no tags, identities, profile paths or provider output.
- Match the active reported status identity to unchanged before/after metadata. Distinct cached account IDs or a signed-in flag alone do not prove separate credentials.
- Use genuine `readClaudeAccountMetadataIdentity` tuples directly; never synthesize a metadata document to reuse a parser. Keep the existing reader's ignored close-error limitation explicit and require real native admission separately from joined-status fields.
- Persist every exact attempt before dispatch. Recovery validates current private custody and bindings and reconciles a pending effect; never reset the baseline or replay an uncertain login/logout.
- Native launch tickets bind one persisted attempt and probe to the actual held owner and current receipt. Compose separate source and runtime checks immediately before launch. A native restore with a pending attempt remains recovery-only and cannot persist fabricated settlement to regain launch authority.
- Keep owner sign-in and interruption attestations explicit. Never inspect credentials or Keychain items, infer principal lookup provenance, or invent provider endpoints.
- New 22-step native runs require authenticated `browserMode:owner_manual` before any provider child and use the separate manual-browser foreground binding. Historical version-2 receipts without that field remain verifiable and recovery-only for pending attempts; absence never admits the new ceremony. Other native custody creators retain their existing policy.
- Preserve native logout, exact child/stream join and owned cleanup as separate facts. Unknown cleanup retains recovery scope.
- Paired identity probes require common run/attempt/key and executable binding, ordered A/B profiles and disjoint private roots. Join both projectors, original settlements and the actual retained-instance overlap before returning. Partial failure must reject the peer rendezvous and collect every started child.
- Keep native overlap hooks private. Explicit fixture composition always reports `credential_free_fixture`; neither supplied receipts nor fixture booleans may become `native_process` authority.
- Native observer fixtures require `OOMPA_CLAUDE_MACOS_NATIVE_OBSERVER=1` and the installed absolute scheduler's mac-native lane. Tests use only the unchanged synthetic status program and fresh empty configurations.
- Cleanup removes only the four bound profile/temporary roots, with persisted per-root intent and exact removal reconciliation. Retain the protected run evidence scope, proof key, authenticated receipt and owner lock; never substitute blanket root deletion or proof-key deletion for verification.
- Native custody fixtures require `OOMPA_CLAUDE_MACOS_AUTH_CUSTODY_NATIVE=1` and the installed absolute host scheduler's mac-native lane. Create only fresh temporary roots and noncredential keys; do not access a provider, credential document, Keychain or personal profile.
- Keep cleanup-root intent and removal events in the authenticated journal. A partial quarantine or absent path never implies process collection, remote rollback or permission to repeat authentication.
