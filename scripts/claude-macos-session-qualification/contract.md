# Darwin session qualification

The private `runNativeDarwinSessionQualification` library entry prepares a fresh, guarded session qualification through Oompa's existing production Claude adapter. It has no CLI command and does not change managed macOS availability. All 18 driver/turn cases pass across the focused runs, including the native source-root refusal. The pure custody tests pass 10 cases with 357 assertions, and the combined native custody/owner regression suite passes 29 cases with 498 assertions. Focused strict types and lint pass; repository integration remains pending. Native fixtures use synthetic source and summaries and retain their exact private roots after owner release. No provider runtime or authenticated session evidence has been collected for this boundary.

The native entry first requires the supplied repository root to be the actual source tree containing its module, before inspecting temporary directories, capturing admission or creating custody. It cannot borrow a different checkout's provenance. The native input fixes an exact repository commit and the independently admitted pinned executable. It accepts a captured environment and cancellation signal, with no operation, profile, provider account, runtime or process override. The source admission checks current bytes against the reviewed signed artifact; it does not run a new signature or revocation check. The session owner creates its own fresh private profile, temporary directory, project, runtime directory and authenticated evidence under a short fixed temporary namespace. The outer native caller must start with `TMPDIR=/private/tmp`; the entry checks the actual canonical temporary root before creating custody, preserving the existing authentication binder without mutating the process environment. Minted profile and provider account IDs are parsed through production schemas before constructing the qualification's generation-one authority.

## Fixed sequence

1. Observe the exact version, strict login help and strict logout help through three bounded detached children. Retain the actual resolved runtime for subsequent calls.
2. Observe the fresh profile signed out. Inherited authentication refuses the run before login or logout.
3. Run provider-owned foreground Claude.ai login through the original terminal. Join its direct child and inherited I/O obligations, then require a fresh attempt-bound terminal challenge response. This records the owner's observation; it does not independently identify a human or credential principal.
4. Read a fresh detached, same-probe signed-in identity. Keep only private keyed tags, never the raw account identity or credentials.
5. Start the exact minted provider thread through the production runtime manager, current host-tool binding and production process adapter. Record its actual Darwin process identity and connection.
6. Observe a nonce response, one exact bounded Bash approval, one denial, and an interrupted streaming turn. Every input frame has its own durable intent and one-use dispatch ticket. Unrequested tool calls refuse; the local host-tool callback never supplies fictional success.
7. Close and join that retained child and its natural output EOFs. Create a new manager and resume the same thread only from this positively joined retained incarnation. Require a different process identity and connection, then observe another nonce response and joined close.
8. After the final session and callback transport joins, perform fixed native logout and observe signed out. Retain the private roots, proof key, authenticated journal and owner lock; release the owner once.

The journal admits at most 17 operations, 16 dispatches per operation, 128 dispatches in total, 64 KiB per input frame and a bounded 64 KiB checkpoint. The stream observer bounds each scenario to 1,024 facts and 16 KiB of assistant text. The production process wrapper additionally bounds captured output to 2 MiB per retained child. Each automated turn has a 90-second deadline. Foreground login uses the existing explicit cancellation and child-join policy, without an ordinary ceremony timeout.

## Failure and evidence

The journal persists operation intent and dispatch before native effects. A process/frame ticket belongs to the exact returned attempt, current receipt generation and held owner; it can be consumed once. Source/executable validation remains a separate actual check immediately before the effect. A frame snapshot supplies both its keyed receipt tag and the exact bytes passed to the production writer.

Any refused or ambiguous effect stops the sequence. The driver may close only its retained session handles and callback transport; it does not dispatch another turn, resume, logout, delete profiles or infer recovery from PID absence. Failed persistence and owner release remain separately visible. An unjoined owner-prompt write, failed production identity inspection, failed runtime-manager close or failed callback-server startup remains sticky cleanup uncertainty, even when the provider child later exits. All available exact resource handles still receive their independent cleanup attempts. Known partial-creation roots are returned as recovery locators. There is no restore, retry, removal or crash-reconciliation API in this unit. Every recovery-required outcome also retains the in-process entry latch. This is a harness refusal, not durable recovery authority across a later process restart.

Approval/denial evidence records the exact locally acknowledged control response and provider terminal facts. It does not prove tool-side-effect absence or independent provider interpretation. Interruption additionally requires a newly acknowledged control frame; the production adapter marks its terminal interruption status locally, so the result does not prove that the control caused an early stop. A turn settles only after its matching summary and the production assembler's closed result tail; the invalid-accounting marker joins delivery without asserting accounting validity.

Session closure proves the retained direct child and natural stream joins supported by the production adapter. It does not prove the absence of provider-created descendants or simultaneous Keychain access. Foreground login inherits the owner's terminal, so it proves its owned I/O obligations and direct-child join rather than captured-output EOF. Detached status/version/help/logout retain their separately tested target, stream and inspector joins.

A successful result has `sessionSequenceComplete:true` while `activationAuthorized`, `managedMacAdmission`, `daemonRestartQualified`, `ambiguousRecoveryQualified` and `privateRootsRemoved` remain false. Exact manager recreation and same-thread resume do not stand for an actual daemon restart. The separate two-account credential-isolation ceremony, native custody evidence, authenticated session run, real daemon restart and uncertain-mutation recovery, and owner-machine install/upgrade acceptance remain required before the corresponding product claims.

The credential-free runner is a separate orchestration fixture with explicit fixture provenance. Its callbacks cannot construct native custody or promote their result to a live qualification. Synthetic tests validate ordering and refusal; they do not establish provider behavior.
