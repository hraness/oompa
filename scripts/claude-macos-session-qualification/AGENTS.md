# Guidelines

- Keep this boundary separate from the production platform policy and the two-account authentication qualification. Never reuse its profiles, cleanup receipts or dispatch tickets.
- The native entry accepts only exact source/executable coordinates, an environment snapshot and cancellation. Keep operation order, roots, profile identities, runtime and process factories internally fixed.
- Persist each operation and dispatch before its effect. An uncertain result closes this run; retain the exact roots and evidence without replay, another provider writer or opportunistic logout.
- Bind every process and frame to the held owner, exact receipt, source and executable. Receipt summaries and fixture observations are evidence, not launch authority.
- Keep provider identities HMAC-tagged and credentials, raw output, reasoning and frame contents out of receipts. Keep only bounded closed observations.
- Do not claim credential isolation, provider-descendant containment, daemon restart, crash reconciliation or daily-driver activation from this narrower session sequence.
- Ordinary tests must not execute a provider, access Keychain or use a personal profile. Root owns any future native or authenticated acceptance and repository integration.
